### 2-3. メールおよびLINEでの返信ルール

#### 原則ルール

1. メール・LINE返信時は必ず宛名を書く
2. 文頭に必ず挨拶文を入れる

#### 基本フォーマット（必須）

```
〇〇様（社名がある場合は社名も入力）

いつも大変お世話になっております。
株式会社プロパゲート カスタマーサポートでございます。
```

この形式を必ず入れてから本文を開始してください。

#### 例外

- 会話がラリー形式で進んでいる場合
- 1時間以内の返信など、明確に文脈が続いている場合

上記のケースでは、文脈に応じて省略可とします。ただし「基本は入れる」が前提です。

#### なぜここまで徹底するのか

- 私たちはBtoBの会社であること
- 一つひとつのやり取りが信頼残高になること
- 文章の第一印象が会社の印象そのものになること

スピードは重要です。しかし、丁寧さを削ってはいけません。「慣れ」や「なんとなく」で崩さないよう徹底をお願いします。

### 2-4. 顧客対応の共通原則

#### 「ノー」で終わらせない

「できません」「対応していません」で終わらせるコミュニケーションは避けてください。できないことを「できます」と言う必要はありませんが、そこで終わらせると、お客様からは「プロパゲートに頼んでいる意味がない」と受け取られ、解約につながった事例があります。

大事なのは「ノー」と言うことではなく、**"ノーで終わらせない"こと**です。対応が難しい場合でも、以下のように「どうすれば前に進むか」を提示してください。

- 代替案を出す
- 近い解決策を提案する
- できる範囲を伝える
- 専門担当に確認する
- 一度社内で相談してから返答する

判断に迷うケースは自己判断で完結させず、**必ず相談**してください。

| 相談内容 | 相談先 |
| --- | --- |
| PS間で解決できそうなテーマ | 松本さん |
| ディレクターに問いたいテーマ | 林さん |

#### 素材共有・修正依頼は修正ツールに集約

AI制作案件で、お客様から画像・動画・ドキュメント等の素材や修正依頼が届いた場合は、必ず**修正ツール（サイトアノテーター）へのアップロードをご案内**してください。

- **LINE・メール上での素材受付・修正依頼受付は不可**
- **ギガファイル便・Googleドライブ・Dropbox等の外部共有サービスでの素材共有も原則NG**

「画像が大きすぎて貼れない」「枚数が多い」等のご相談があった場合も、外部サービスではなく修正ツールへのアップロードをご案内してください（素材・修正内容が複数の場所に分散すると、対応漏れ・確認漏れ・最新版不明などのリスクが発生するためです）。

※ 修正ツールURLは制作進行シート AL列より確認可能

> 📌 **AI 一次回答（自動返信）での扱い（2026-10-01〜／的場さん・鈴木）** — AIサイトのお客様からメール・LINE で修正・更新の依頼（文章・画像の差し替え、記事の追加、素材の送付など）が届いた場合、AI 一次回答は**依頼を受け取り**、そのうえで「なお、修正内容や画像をまとめてお送りいただける貴社専用の修正ツールもございますので、よろしければご活用ください」と、紹介する程度の言い方で修正ツールの URL を添えて返します（お客様の入口をメール・LINE から修正ツールに変えさせると手間になり、そのまま返信が途絶えて対応が遅れるため）。何度目の依頼でも受け取り、「次回からは修正ツールで」とお願いしたり、案内を強めたりはしません（2026-10-02 鈴木）。下の送付テンプレのような断る言い方もしません。チケットは**ディレクター・修正担当に振らず、オープン・担当なし・部署 PS** で残すので、PS が拾って [12-1](#12-1-受付時の対応) の 2 から対応してください。

> 📝 **修正内容の文章が画像で届いた場合（2026-10-01〜／的場さん）** — メール・LINE でのサイト修正依頼で、追記・差し替えしてほしい文章が**画像で**送られてきた場合（例: 画像を添付して「画像内の文章を実績ページへ追記してください」）は、**画像ではなく該当の文章をメール・LINE に文面（テキスト）でいただくよう返信**してください。修正対応者が文章をそのままコピーして転記できるようにするためです（画像から書き起こすと誤字が発生するおそれがあります）。

#### 修正ツールが動作しない不具合の連絡があった場合（2026-08-18〜）

先方から「修正ツールの『コメントを入れる』を押しても作動しない」「修正ツールのボックスが出ない・選択ができない」といった不具合のご連絡をいただくことがあります。**基本的には先方側のPC・ブラウザ環境が原因であることが多い**ため、まずは以下の3点をご案内してください（社内での確認では問題なく動作するケースがほとんどです）。

- **別のブラウザで開く**（推奨は最新版 Google Chrome）
- **シークレットモード（プライベートモード）をOFFにする**
- **テザリング等、社用Wi-Fi以外の回線からアクセスする**

上記をご案内しても改善しない場合は、開発チームへエスカレーションしてください。

#### 修正ツールの対応端末・アップロード可能なファイル形式（2026-08-19〜）

**スマートフォンからの利用について**

修正ツールは案内上「PC専用」としてご案内していますが、**実際にはスマートフォンでも操作自体は可能**です（ただしPCに比べて操作しづらいため、修正内容のご入力は原則PCからのご案内とします）。「PCを利用できない」というお客様には、まずスマホでの操作をご案内し、その上で対応が難しい場合はテキストで修正内容をいただくようご案内してください。

**アップロード可能なファイル形式**

修正ツール上に直接アップロードできるファイル形式は以下です。

- 画像：PNG / JPG / GIF / WebP
- 動画：MP4 / MOV / WebM

※ **PDF はアップロード不可**です。

**正常にアップロードできているかの確認方法**

修正ツール上のコメントに、アップロードした画像・動画が表示されていれば、正常にアップロード完了しています。

#### Wix案件で先方からデータ共有があった場合

先方からいただいた期限付きファイル（ギガファイル便など）は、必ず確認担当者がGoogleドライブへ格納します。共有期限切れが発生しないよう管理を徹底してください（期限がないデータは格納不要）。

1. お客様へ一次返信
2. [データ格納ドライブ](https://drive.google.com/drive/u/0/folders/1T8VzfQ7NKj_Rsl9idlnXYcRql04DL2do) に案件の受注月ごとに管理

※ [ドライブの運用について](https://docs.google.com/document/d/1QVQnOkWqzxx7saQTqViF7hzHN8IQSk5psiV_1D_afx0/edit)

#### 複数件同様の連絡（データ送付）があった場合

- **デモアポ前の案件**: 複数ご連絡いただいても問題ありません
- **デモアポ後の制作中案件**: 通常通り修正ツールでのご依頼をご案内してください
- 同様のご連絡を複数件いただいた場合は、すべてを割り振るのではなく **1件のみ割り振り**を行い、内部メモに「複数件同様のご連絡あり」と記載して担当共有してください

#### 制作中案件の「たらい回し」防止

制作中の案件は、基本的にディレクターが対応します。PSで対応しきれない内容を、PS側で一時受けして「確認します」と返すのではなく、**すぐにディレクターへチケットを振り、ディレクター側で完結**させてください（「PSが受ける → 確認します → ディレクターに確認 → 返答」の流れが続くほど、お客様には"たらい回し"に感じられるためです）。

| PSで回答する内容（カスタマーサポート名義で返信） | ディレクターへ渡す内容（一時受けせず即チケット） |
| --- | --- |
| 修正の依頼内容 | 制作内容に関する判断が必要なもの |
| 次のステップに進める依頼 | デザインや構成に関する確認 |
| ドメインに関する案内 | 進行状況や納期に関する具体的な確認 |
| メール設定に関する案内（初回案内） | お客様の温度感が高い内容 |
| 契約内容に関する案内（何を契約していていくらか 等。kintone・マニュアル・ナレッジで答えられる範囲。2026-10-05 林さん確認） | PSで回答すると認識ズレが起きそうな内容 |
| その他、PS側で回答可能な定型的な内容 | |

## 6. 制作進行シートの基本操作

### 6-1. 基本原則

PSの最も重要な役割は、**顧客からの連絡を受けて、M列またはN列のステータスを次のフェーズに変更し、適切な担当に連携すること**です。

> ⚠️ **Q列（ball_holder）は自動計算です。確認も変更も不要です。** M列・N列のステータスを変更すれば、Q列は自動的に正しい値に更新されます。

### 6-2. ルーティング手順（共通フロー）

| Step | 内容 |
| --- | --- |
| 1 | 制作進行シートの C列（client_name）で顧客名を検索し、案件を特定する |
| 2 | M列（AI制作）または N列（Wix制作）の現在のステータスを確認する |
| 3 | 連絡内容に応じてステータスを次のフェーズに変更し、同時に **T列（phase_deadline）** に新しいフェーズ期限日を設定する |
| 4 | 下表に従い、担当部署・担当者へ連携する |

> 💡 **T列（フェーズ期限日）と K列（納品希望日）は別物です。** T列は各フェーズの作業期限、K列は営業が設定する全体の納品期日です。

#### 連携先の判断表

| 変更後ステータスの制作担当 | 担当部署 | 担当者 |
| --- | --- | --- |
| ポリッシュが作業するフェーズ | **記入不要** | 制作進行シートのステータス変更のみでOK |
| ディレクターがチェックするフェーズ | ディレクター | I列の担当者名 |
| 営業が対応するフェーズ | 営業 | H列の担当者名 |
| Wixデザイナーが作業するフェーズ | Wixデザイナー | J列の担当者名 |
| PSが直接対応する場合 | 記入不要 | — |

### 6-3. カラム早見表（PS関連）

| 列 | 名前 | PSの操作 |
| --- | --- | --- |
| C | client_name | 案件検索に使用 |

| I | director | ディレクターの連携先を特定 |
| J | wix_producer | Wixデザイナーの連携先を特定 |

### 6-4. タブ自動移動ルール

以下のタブ移動はGASにより自動で行われます。PSの手動操作は不要です。

| 移動 | 条件 | PSへの影響 |
| --- | --- | --- |
| メイン → **長期未返信** | Q列＝顧客 かつ T列から30日経過（毎朝7時自動チェック） | メインタブから消えるが移動しているだけ。顧客から返答があればステータス変更で自動復帰 |
| メイン → **制作中解約** | kintone受注ステータス＝解約（毎朝7時自動チェック） | 解約手続きを行った案件は自動で移動される |

| メイン → **完了** | AM〜AR列の6条件達成（自動。確認ダイアログは 2026-06-05 に廃止） | ディレクターが完了処理を行うと自動移動 |

### 6-5. 記入時の注意事項

- ステータス変更は、**実際のメール送信・提出と連動**させること（ステータスだけ変更してメール未送信は厳禁）
- AI制作とWix制作でステータスの遷移が異なるため注意すること
- 大井さんの案件は全て**旧進行シート**でステータス変更・納期変更する（共有事項がない限りSlackでの報告も不要）
- ステータスを誤って変更した場合は、速やかに元に戻し担当へ報告すること
- 制作中案件でドメイン接続ステータスに進んだものは、M列・N列ではなく **AQ列のみ**を変更する。同時に修正があった場合は M列またはN列を「修正中」に変更
  - ※ AI統合ステータス／Wix統合ステータスの修正と合わせてドメイン接続を依頼された際、M列・N列でステータスを変更してしまうと、修正依頼が来ているかポリッシュ側で判断できなくなるため
- 公開のご連絡や制作を次のステップへ進める場合など、**制作進行シートのステータス変更のみ**でOK（Propagate Desk上でのチケット依頼は不要）
  - 例：次の制作ステップへ進行して問題ない旨の連絡をいただいた場合／ドメイン接続や公開作業へ進める確認が取れた場合
- 修正内容の確認も、複雑な内容でなければお客様に返信のうえ、制作進行のステータスを変えるのみでOK

## 8. 納期・提出日ルール

現在（2026.01〜）、プロパゲートでは **Wix制作** と **AI制作** の2つの方法でサイトを制作しており、どちらで制作しているかによって納期・提出日・対応に違いがあるため十分注意してください。

### 8-1. WixとAIのどちらで制作したサイトか判断する方法

ブラウザに [Wappalyzer](https://chromewebstore.google.com/detail/wappalyzer-technology-pro/gppongmhjkpfnbhagpmjfkannfbllamg?hl=ja) 拡張機能を入れることで、サイトを開いて即時判断可能です。

**AI制作の場合**: JavaScript に **Next.js**、フレームPaaS に **Vercel** が必ず入っています。

### 8-2. T列（phase_deadline）フェーズ期限日の設定基準

| プラン | デモサイト制作 | 修正 | スマホ最適 |
| --- | --- | --- | --- |

## 10. 顧客対応の手順（Propagate Desk）

**URL**: https://propagate-desk.vercel.app/ に自身のアカウントでログイン

**参照先**: [Propagate Desk 利用マニュアル](https://www.notion.so/Propagate-Desk-{NOTION_PAGE_ID}) / [PS向けマニュアル](https://www.notion.so/PS-{NOTION_PAGE_ID}) / propagate-desk チャンネル

### 10-1. チケット対応順序

原則として、**古いチケットから順に**対応してください。以下の場合は例外として優先対応して問題ありません。

- 直近自身が対応したチケットに即時返信があった場合
- 打ち合わせ直前の確認や日程関連の連絡
- 緊急性が高い内容
- クレーム対応

※「かしこまりました」「よろしくお願いいたします」などのお客様からの返信は、迷惑メールや営業メールではないため、引き続き対応分析のカウント対象となります。

### 10-2. 対応期限

原則、当日受信したチケットについては当日中に一次対応・回答を行うこと。

| 受信タイミング | 対応期限 |
| --- | --- |
| 当日午前中に受信 | 当日 17:00 までに必ず対応 |
| 当日午後〜17:00 までに受信 | 当日中に必ず対応 |
| 当日 17:00 以降に受信 | 翌営業日の 12:00 までに必ず対応 |

※ Propagate Desk 上にチケット受信日時が表示されるため、必ず受信日時を確認したうえでスピーディーな対応を徹底すること。

### 10-3. チケット作成

1. パートナー名から対象パートナーを検索
2. 右上の「新規チケット」をクリック
3. 内容を入力し送信

※ Desk上からチケット作成・メール送信が可能です。

#### 社内用チケット（電話）の作成

電話対応の業務依頼は、Propagate Desk から社内用チケットを作成してください。

1. 顧客ページから「新規チケット」をクリック
2. 上部タブで「電話」または「その他」を選択
3. 内容を入力して作成

※「電話」「その他」で作成したチケットは、**お客様へ通知されません**
※ 1つのチケットに複数担当者を設定することも可能です

### 10-4. 営業メールの受信停止

Google や Wix などからの自動通知、頻繁にいただく営業メールは、該当パートナーを「受信停止」にすることで、次回以降のメール受信時にチケットが作成されなくなります。

1. 該当チケットを開く
2. 画面右上の「編集」をクリック（パートナー詳細ページ）
3. 「受信停止」をクリック
4. ステータスが「受信停止中」になれば完了

**以降の動き**

- 同じメールアドレスから届くメールは自動で無視される（チケット作成なし・AI返信案も生成されない）
- 過去のチケットも一覧から非表示になる
- 再度受信したい場合は「再開する」で解除可能

**注意点**

- 現在届いているメールは受信済みのため、不要であれば「解決済み」にしてください
- 2通目以降は自動で無視されます

### 10-5. LINE の kintone連携

LINEで連絡が来た顧客について、Propagate Desk で「kintone連携されていないチケット」を見つけたら、kintone の該当レコードに「LINE ID」の入力をお願いします。これにより、その顧客の以降のLINEは正しい案件のチケットに紐付きます。

**連携されていないチケットの見分け方**

1. Propagate Desk でチケットを開く
2. 右パネルの「案件」欄を確認
3. 「未連携」「案件なし」などの表示なら対象

**kintone連携手順**

1. Propagate Desk で該当パートナーの連絡を開き、右欄の顧客情報に表示されている LINE ID をコピー
   - `U〜` で始まるID：個人LINE
   - `C〜` で始まるID：グループLINE
2. 公式LINE（chat.line.biz）で該当LINEを確認。対象の LINE アカウント（カスタム表示名＝パートナー名）を検索。同じパートナー名で複数出てくることが多いので、今回連絡が来たLINEがどれかを確認
3. kintone で該当パートナー名を検索（そのパートナーの全レコード＝全サービス／案件が表示される）
4. 公式LINE と kintone を見比べて対応関係を判断（過去メッセージ内容、カスタム表示名のサフィックス、社内ナレッジなどから判断）
5. kintone の該当レコードの LINE ID 欄に、コピーしたIDを貼り付けて保存
   - 1つのLINEが複数案件にまたがる場合 → 該当する全レコードに同じLINE IDを入力
   - 案件ごとに別のLINEがある場合 → それぞれのレコードに別々のLINE IDを入力
   - **1つのレコードに複数のLINE IDを紐づける場合** → LINE ID 欄に複数入力でき、**2つ目以降は「,」（カンマ）で区切って**入力する

**入力後の反映**: kintone保存後、数十秒〜数分でシステムが自動同期されます。そのチケットは正しい kintone顧客に紐付き、正しい案件にアサインされます。

> ⚠️ LINE IDを間違えると別人のメッセージが流入する可能性があります。**コピペで正確に入力**してください。

> 📌 **kintone にアドレスや LINE ID が登録済みなのに Desk と紐付かない場合（2026-10-05〜／的場さん・小林さん）** — 原因不明のことが多く、手動では紐付きません。都度 `#propagate-desk` で **@小林 航太朗さん** にメンションして依頼してください（Desk の顧客 URL を添える）。

## 11. ドメイン接続

参照: [ドメイン／GSC／GA／Workspace 設定依頼管理 運用マニュアル](07-ドメイン-GSC-GA-Workspace設定依頼管理-運用マニュアル.md)

> 📌 **ドメイン接続と公開の進め方（2026-10-02〜／林さん・工藤さん）** — 修正サイトの「確認OK」から納品までの流れです。
>
> - **修正サイトの「確認OK」が来たら**、PS がドメインの案内に進む
> - **「ドメイン接続と公開をお願いします」とまとめて依頼が来ても**、すぐに「公開を進めます」とは返さない。まず、ドメインをどうするか（弊社で新規取得／貴社で接続／接続代行）を確かめる
> - **A 弊社で新規取得（[11-3](#11-3-新規ドメイン取得)）**：ローンチコンソールで接続と公開が一度に進む。ドメインが確定した時点で、お客様に「このドメインで接続し、そのまま公開まで進めます」と一文伝える（伝えずに進めると「勝手に公開された」と受け取られるため）。確定したらディレクターに「依頼中」で渡す。修正が終わる前に接続とフォーム実装を先に済ませるケースも、A の前倒しとして扱う
> - **B-1 貴社で接続／B-2 接続代行（[11-4](#11-4-先方ドメイン使用)）**：接続と公開は別の工程。接続が終わっても、すぐには公開しない
>   - B-1：お客様の「設定しました」→ ディレクターが接続を確認 → 公開
>   - B-2：石橋さんの「接続完了」→ PS が完了報告とタイトル・ディスクリプションを送る → お客様の「公開OK」→ ディレクターに公開を「依頼中」で依頼。接続直後に問い合わせが来ることがあるので、代行が決まったらフォームの実装も並行して進める

### 11-1. ドメイン接続の案内（AW列「ドメイン接続希望欄」）

> ✅ **2026-07-08〜 ドメイン接続の案内メールは自動送信になりました。** 原則としてPSから手動で案内する必要はありません。

ただし、お客様から**テキストで**ドメイン接続のご依頼（「サイトの方OKです」等の連絡）があった場合は、制作進行シートの **AW列「ドメイン接続希望欄」**（ヒアリングシート回答時点でお客様が希望した接続方法）を確認のうえ対応します。

| AW列（ドメイン接続希望） | 対応 |
| --- | --- |
| **先方ドメイン接続（先方接続）** | 接続希望で間違いないか確認 → 接続の場合は Vercel で DNSレコードを発行・共有（送信用テンプレは別途共有） |
| **先方ドメイン接続（接続代行）** | このドメインで接続して問題ないか確認 → 接続代行で進めてよいか確認（有料・税込 11,000円）→ ID・パスワードをご教示いただく |
| **弊社新規取得** | ヒアリングシートの「新しく取得するドメインに入れたい文字（キーワード）」の回答を確認 → 取得可能なドメインをバリュードメイン上で確認し、お客様へ候補をご提案 |

> ⚠️ 自動メールの二重送信を防ぐため、**AQ列に値が入力されていると、サイト進捗確認の自動 push メールは送信されません**（M・N列のステータスに関係なく。2026-06-26〜、2026-09 に実装修正）。ドメイン接続のやり取りに入ったら、AQ列を進めてください。
>
> - サイト内容OK → ドメイン接続に進む際は、**AQ列を「ドメイン接続方法確認中」または「ドメイン接続依頼中」に更新**する
> - **M・N列は修正・公開のときのみ更新**（ドメイン接続に進んだだけでは変更不要）
> - 修正とドメイン接続を並行している場合は、**M・N列を「修正中」にしつつ AQ列も進める**
>

**用語の一言説明**（お客様に聞かれたときに使う。2026-10-06）

- **Aレコード**：ドメイン（例: example.com）を、サイトが置いてあるサーバーの番号（IP アドレス）に結びつける設定。これを弊社の値にすると、そのドメインで新しいホームページが表示される
- **CNAMEレコード**：www 付きのアドレス（www.example.com）を、別の名前（弊社の接続先）に結びつける設定。www 付きでも同じサイトが開くようにするために入れる
- **MXレコード**：そのドメインのメールをどのサーバーで受け取るかの設定。ドメインのメールを使っているときは、この値を変えない・消さない（変えるとメールが届かなくなる）。ホームページの接続で足すのは A と CNAME だけで、MX は触らない

#### DNS の設定で気をつけること（旧ディレクターマニュアルから。2026-10-06 移行）

弊社で接続を代行するとき・お客様に案内するときの両方で気をつけます。

### 11-6. アカウント情報・所有権の開示ポリシー（2026-08-19〜）

先方から「サーバーやドメインのアカウント情報を教えてほしい」「サイト管理画面のログイン情報がほしい」といったご依頼があった場合の考え方です。**弊社が管理している各種ツールのID・パスワード（ログイン情報）は、原則一切お渡しできません。**

#### 1. サーバー（Vercel）の接続・管理情報について

弊社で接続・構築したサイトは、**弊社のサーバー（Vercel）で接続**しています。先方が用意したサーバーに接続することも技術的には可能ですが、弊社が管理している Vercel のアカウント情報をお渡しすることはできません。Vercel の情報を受け渡すことは、**サイトの所有権そのものを譲渡する**ことになってしまうためです。

#### 2. サイト管理画面の編集権限について

サイト管理画面の編集権限をお渡しすることも、サイト所有権の譲渡にあたるため、**ID・パスワードなどのログイン情報は開示できません**。

#### 3. ドメインについて

弊社でドメインを取得した場合、そのドメイン情報（ログイン情報など）をお渡しすることはできません。ドメインの譲渡依頼があった場合は、**オースコード（AuthCode）を通じてドメインを移管（譲渡）**する形になります。手順は [11-7](#11-7-ドメイン譲渡弊社他社の手順2026-10-06) を参照してください。

**譲渡手数料（2026-10-06〜／林さん）** — 時期・タイミングに関係なく、次のとおりです（36ヶ月経過後も同じ）。

| ドメインの元 | 譲渡手数料 |
| --- | --- |
| **弊社が新規取得**したドメインを譲渡する | **10万円** |
| **先方所有**のドメインを弊社に一度移管していて、それを**お返しする** | **なし** |

> 📌 **ドメイン移管が必要かの判定（弊社でのドメイン所持確認方法）（2026-09-14〜）** — 解約・所有権譲渡などでドメイン移管のご依頼があった場合は、まず**弊社が実際にそのドメインを所持しているか**を確認してから対応します。所持していなければ、そもそも移管は発生しません。
> 1. [バリュードメイン](https://www.value-domain.com/) にログイン（ログイン情報は社内のパスワード管理ツールを参照）
> 2. 「ドメイン」＞検索バーに該当のドメイン名を入力（`http`・`www` は削除）
>    - ドメインの設定操作の画面に該当ドメイン**あり** → 弊社所持のため **ドメイン移管対象**（AuthCode で移管。弊社の新規取得なら10万円、先方所有ドメインのお返しなら手数料なし）。どちらかは、バリュードメインで該当ドメインの **WHOIS 情報**を見て判断します：**弊社の情報**なら弊社所有（10万円）、**弊社以外（先方）の情報**なら先方所有（お返し・手数料なし）（2026-10-07 林さん）
>    - Wix で接続しているサイトの場合は、ドメインが Wix に移管されていることがあります。Wix の対象案件のダッシュボード＞ドメイン設定のドメインページを見て、**契約のドメイン更新期間が出ていれば先方所有**、出ていなければそれ以外、と判断します（2026-10-07 林さん）
>    - ドメインの設定操作の画面に該当ドメイン**なし** → そもそも弊社所持ではないため、**ドメイン移管は不要（不可）**

#### ◆ 例外（ログイン権限を付与できるもの）

以下のツールは、弊社の管理者権限を渡すのではなく、**先方側でアカウントを設定していただき、ID・パスワードでログインしてご利用いただく**形になります。

- AI制作案件における**ブログCMS・投稿CMS**
- **Propagate AI（PA）**

AI案件のブログCMS・投稿CMSについては、管理者権限の付与ではなく、**Propagate AI の管理画面から入ってログイン権限（編集者権限）を付与**する形になります。手順は以下の通りです。

1. https://www.propagate-ai.com/admin/blog-cms を開き、サイト名で検索してサイト詳細を開く
2. 名前の登録があるサイトはブログが実装されている状態
3. 特定のメールアドレスに編集者権限を付与したいときは、サイト詳細の「メンバー管理」にメールアドレスを入力して「追加」を押す（そのメールアドレスでログインが可能になる）

> 詳細なブログCMSの権限付与手順は [21-3](#21-3-aiサイトのブログcms)、PAのアカウント対応は [22-4](#22-4-アカウント関連の対応) を参照してください。

- 移管の手数料は、お客様が**今の管理会社**に払います（平均 1,000〜3,000円。かからない場合もあります）
- 移管したあとは、弊社がバリュードメインに払うドメインの更新費用（年額）と**同じ額を、年額でお客様に請求**します。金額は下の手順 4 の画面で確認します
- 請求のしかた（2026-10-07 林さん）：オプションの kintone レコードを発行し（作り方は [11-7](#11-7-ドメイン譲渡弊社他社の手順2026-10-06) の「3 の操作」と同じ。受注金額は確認した税込の実費）、Slack「finance-sales確認」で請求書の発行を依頼する（税込実費・年額）

**始める前に**

- お客様が**そのドメインでメール（独自ドメインメール）を使っているか、必ず確かめる**。違うところを設定するとメールが使えなくなります（2026-10-07 林さん）
- 上の 11-7「つまずきやすい点」の**移管できない時期**（期限まで14日以内・登録から60日以内など）に当たらないか確かめる

**移管が終わったら** — 弊社のバリュードメインで、**ネームサーバー接続**でサイトにつなぎます（2026-10-07 林さん）。

**お客様のドメインがすでにバリュードメインにある場合**

同じバリュードメインの中での移動になります。お客様に次の文を送ります。

```
お世話になっております。
株式会社プロパゲート カスタマーサポートでございます。

ドメインの移管につきまして、弊社もバリュードメインで管理しておりますので、同じバリュードメイン内での移動となります。
お手数ですが、現在ドメインを管理されている会社様に「ドメインの移動先のユーザーIDを（弊社のユーザーID）にしてほしい」とお伝えいただけますでしょうか。
手順は下記のページにございますので、あわせてお送りいただけますと幸いです。
https://www.value-domain.com/userguide/manual/localtrans

お手数をおかけして大変申し訳ございませんが、何卒よろしくお願いいたします。
```

- 弊社のユーザーIDは、社内のパスワード管理ツールで確認します
- お客様から「移動しました」と連絡が来たら、弊社でドメインを接続します

**お客様のドメインがバリュードメインにない場合**

1. お客様に AuthCode（オースコード）の発行を頼む

    ```
    お世話になっております。
    株式会社プロパゲート カスタマーサポートでございます。

    ドメインの移管につきまして、現在ドメインを管理されている会社様に「AuthCode（オースコード）を発行してほしい」とお伝えいただけますでしょうか。
    発行されましたら、こちらにご共有いただけますと幸いです。

    お手数をおかけして大変申し訳ございませんが、何卒よろしくお願いいたします。
    ```

2. AuthCode が届いたら、バリュードメインにログインする（ログイン情報は社内のパスワード管理ツール）
3. 「ドメインの移管」のページを開く
4. ドメイン名を入れ、「移管可能かチェックする」にチェックを入れて「移管可否と料金確認」を押す。**ここに出る金額が、お客様に年額で請求する金額**
5. 状態に問題がなければ AuthCode を入れて「確認画面へ」を押す
6. 「レンタルサーバー同時申し込み」のチェックは**外して**申請する
7. お客様に次の文を送る

    ```
    お世話になっております。
    株式会社プロパゲート カスタマーサポートでございます。

    ドメインの移管につきまして、弊社での申請が完了いたしました。
    お手数ですが、現在ドメインを管理されている会社様に「ドメインの移管申請を承認してほしい」とお伝えいただけますでしょうか。

    何卒よろしくお願いいたします。
    ```

8. お客様から連絡が来なければ、1日おきくらいに、3 と同じページの「移管中のドメイン状態を確認」で状態を見る。承認されていれば弊社でドメインを接続する。失敗していたら 2 からやり直す
9. 移管が終わるまで 5〜7 日ほどかかることがあります

**.jp・.co.jp の場合**

- 流れは同じですが、申請するページが別です（バリュードメインの .jp 用の説明 https://www.value-domain.com/userguide/manual/zjptransfer ）
- 申請のときに**期間の延長はしない**でください

> 💡 移管について詳しくはバリュードメインの説明ページ https://www.value-domain.com/userguide/manual/transfer を見てください。

### 13-3. サブドメインのご案内（2026-07-29〜）

> ⚠️ **「サブドメインの用途によっては、現在のサイトへページを追加する」という案内は誤り。** サブドメインとページ追加は別の対応です。ご案内時は下記の切り分けに注意してください。

サブドメインは、現在のサイトに新しいページを追加するものではなく、**基本的には別のサイトを公開するためのURL（別のドメイン）**として扱います。

例:

- 現在のサイト: `example.com`
- サブドメイン: `recruit.example.com`

この場合 `recruit.example.com` は現在のサイト内の1ページではなく、**別サイトとして制作・管理**する形になります。そのため、サブドメインを使って新しいサイトを公開する場合は、**原則として新規契約が必要**です。

一方、現在のサイト内にページを追加する場合は、サブドメインではなく以下のような**ページ配下のURL**となります。

- `example.com/recruit`
- `example.com/service`

この場合は、現在の契約内容に応じて**プランアップまたはページ追加**で対応可能です。

| ご希望 | 対応 |
| --- | --- |
| 現在のサイトとは別に、新しいサイトを作りたい | サブドメインを使用し、**新規契約**での対応 |
| 現在のサイト内に、新しいページを追加したい | **ページ配下**で作成し、プランアップまたはページ追加での対応 |

### 16-3. 解約したお客様のサイトを完全に見えなくする手順（2026-08-31〜）

> 📌 **解約したのにサイトが消えていない、と連絡が来た場合は PS が対応（2026-10-02〜）** — 解約月が終わったあとの非公開・ドメイン外しは、ふだんは大橋昂世さんが行います。お客様から「解約したのに表示されたまま」と連絡が来た場合は、担当ディレクターや大橋昂世さんに振らず、PS がこの 16-3 の手順で対応してください（Wix サイトは [20-3](#20-3-wixサイトの非公開削除依頼への対応2026-08-28)）。

解約したお客様が「サイトを削除（非公開）してほしい」と申し出られた場合の手順です。**サイトの実体は最大4か所に散らばっている**ため、1か所ずつ止めて、**そのつど自分の目で 404（または DEPLOYMENT_NOT_FOUND）を確認してから次に進む**のが鉄則です。

> ⚠️ **「Remove しました」を報告として受け取らない。** 操作した本人も「外したつもり」でいることがあります。実際に、独自ドメインを Remove しても Vercel の確認ダイアログで確定するまで反映されず、サイトが HTTP 200 のまま生きていた事例があります。必ず**シークレットウィンドウ**で URL を開いて 404 を確認してから、お客様へ返信してください（通常のウィンドウだとブラウザに残った古い画面が出て「まだ見える」と誤判定します）。

#### サイトの実体が散らばっている4か所

1. 独自ドメイン（www あり / なし）
2. Vercel の過去デプロイ URL（`...-xxxxxxx.vercel.app` のような長いランダム URL）
3. PA（Propagate AI）の顧客レコードに登録されたサイト URL
4. Google の検索結果

#### 【手順1】Vercel から独自ドメインを外す（担当: 制作でできる／必須）

> 💡 **Vercel でドメイン検索しても該当プロジェクトが見つからない時（2026-09-02〜）** — Vercel の該当プロジェクトは、**Vercel URL（`〇〇.vercel.app`）の「〇〇」の部分（`https://` と `.vercel.app` 以降を除いた箇所）がプロジェクト名**になっています。独自ドメイン名で検索しても出てこない場合は、この**プロジェクト名で検索**すると出てきます（例: `kyaritaggu.vercel.app` → プロジェクト名は `kyaritaggu`）。

1. Vercel の該当プロジェクト → Settings → Domains
2. `www.` が付いた行を探し、右端のメニューから Remove
3. **確認ダイアログにドメイン名を打ち込んで確定するまで、外れません**
4. www なしの行は www へ転送しているだけなので、**www の1件を外せば両方止まります**

> :white_check_mark: 確認: 5分ほど置いてから、シークレットウィンドウで www あり / www なし の両方を開き、404 か DEPLOYMENT_NOT_FOUND になっていること。

#### 【手順2】Vercel のプロジェクトごと削除（担当: エンジニアに依頼／「全部消して」と言われた場合のみ）

- ドメインを外しても、過去デプロイのランダム URL（`...-xxxxxxx.vercel.app`）は**生き続けます**。お客様が過去のメールやブックマークから辿れる状態です。
- プロジェクトを削除すると全デプロイがまとめて消えます。**元に戻せません。** GitHub のソース（非公開リポジトリ）だけが復旧経路として残ります。
- 「全内容削除」と厳密に言われている場合のみ実施し、**エンジニアに依頼**してください。

> :white_check_mark: 確認: お客様に共有した履歴のある `*.vercel.app` の URL を開いて 404 / 410 になっていること。

#### 【手順3】PA に登録されたサイト URL を空にする（担当: エンジニアに依頼／必須）

- PA の顧客レコードにサイト URL が残っていると、**解約後も診断・改善提案のメールが飛び続けます**（過去に、同じ状態で提案メールが送られ続けた事例あり）。
- 制作画面からの操作ではないため、**必ずエンジニアに依頼**します。
- 依頼のしかた: Slack で「解約：顧客ID ○○○○○ の PA サイト URL を止めてください」と伝えれば通じます。**顧客ID は Kintone のレコード番号と同じ**です。

#### 【手順4】Search Console で検索結果から消す（担当: GSC権限者／急ぎのときだけ）

- サイトが 404 になれば検索結果からは自然に落ちますが、**数日〜数週間**かかります。急ぎのときだけこの手順を使います。
- ログインアカウントは 🔒 GSC権限者（社内管理アカウント。担当・GSC権限者に確認）。
- プロパティは **地球アイコンの「ドメインプロパティ」**を選ぶ（重要 → 落とし穴04）。
- 左メニュー「**非表示**」（旧「削除」から名称変更）→「新しいリクエスト」
- タブは「URL を一時的に非表示にする」、URL 欄に `https://www.<サイトのドメイン>/`
- ラジオは「**このプレフィックスで始まる URL をすべて非表示**」を選ぶ。「この URL のみ」だと**トップページ1枚しか消えません**。
- ドメインプロパティなら www あり/なし・http/https が自動で対象になるので **1回の申請で足ります**。

> :warning: **これは一時措置**です。非表示は約6か月で切れます。恒久的に消えるのは「サイトが 404 を返し続けていること」が理由なので、**手順1〜2を飛ばして手順4だけやっても意味がありません。**

#### 踏みやすい落とし穴

1. **「Remove しました」を報告として受け取らない** — 操作した本人も外したつもりでいる。必ず自分で URL を開いて 404 を見てから返信する。
2. **普通のウィンドウで確認しない** — 自分のブラウザに残った古い画面が出て「まだ見える」と誤判定する。確認は必ずシークレットウィンドウで。
3. **ドメインを外して終わりにしない** — `*.vercel.app` の長い URL が残る。「全内容削除」ならプロジェクトごと消すまでが完了。
4. **Search Console のプロパティを間違える** — 登録が www なしのプロパティだけ、というケースがある。そのまま申請しても www のページは消えない（実際に検索結果に出ているのは www 側のことがある）。地球アイコンのドメインプロパティが無ければ、エンジニアに作成を依頼する。
5. **DNS の確認用 TXT レコードを消さない** — ドメインプロパティを作る際、DNS に所有権確認用の TXT レコードを1本追加している。これを消すと非表示申請ごと無効になる。ドメインをお客様にお返しする段階で、エンジニアがまとめて撤去する。
6. **「検索履歴に残っている」を額面どおり受け取らない** — お客様の言う「履歴」がブラウザの閲覧履歴なら、それはお客様のPC内のものなので消せない。ただしサイトが404なら、履歴から開いても表示されない。そこを分けて説明する。

#### お客様への伝え方（そのまま使えます）

**「履歴に残っていて見えてしまう」と言われたら**

```
閲覧履歴の行そのものはお客様のパソコンに残りますが、開いてもページは表示されません。サイトのデータ自体を削除しております。
```

**確認をお願いするとき**

```
お手数ですが、シークレットウィンドウ（プライベートウィンドウ）でご確認いただけますでしょうか。通常のウィンドウですと、以前ご覧になった際の画面がブラウザに残っていて表示されることがございます。
```

**検索結果について聞かれたら**

```
検索結果からは順次消えてまいります。通常は数日ほどですが、お急ぎでしたら削除の申請も可能ですのでお申し付けください。
```

### 16-4. 落としたサイトを戻すとき（2026-10-07〜）

未払いで落としたお客様から入金があったとき、または再契約が決まって契約書を交わしたときは、**PS が 1 営業日以内に**サイトを戻します（2026-10-07 林さん）。落とす作業は、自動になるまでは大橋昂世さんが行います。

### 17-1. kintoneとは

kintone はプログラミングの知識がなくても、ノーコードとAIで業務のシステム化や効率化を実現するアプリがつくれるクラウドサービスです。プロパゲートでは顧客の契約管理・決済連携などに活用しています。

- [kintoneの見方（動画）](https://drive.google.com/file/d/14a-62HlN3LvmAcnb6918mrIiI_y1oebW/view)

> ⚠️ **kintone はクライアントに対し複数発行されます。** 契約しているサービスや打ち合わせごとに発行されるため、1クライアントに対して複数の kintone が発行されるので注意（例：サブスクWEBとスマートSEO両方契約しているクライアントは、レコード番号が異なる2つの kintone が発行されている）。

| --- | --- |
| A確定日 | 口頭受注（口頭でプロパゲートと契約しますと言われている状況） |
| J確定日 | 契約書を締結した日 |

### 17-2-2. 進行ステータス（制作中／納品済み）（2026-09-01〜）

kintone に「**進行ステータス**」フィールドが追加されました。案件が制作中か納品済みかを表し、**Propagate Desk の制作中／納品済み表示もこれをベースに**しています。

- **制作中**: すでに制作進行にあるもの／今後、サブWEBの受注ステータスが J になったもの
- **納品済み**: 制作中ではなく、すでにサブWEBの受注ステータスが J のもの／今後、Propagate AI に登録されたもの

※ 実態とステータスが異なるものを見つけたら、**kintone 上で手動修正**してください。

> **納品済み案件のステータスが「制作中」のまま変わらない場合（2026-09-03〜）**
>
> 通常、納品済みになると kintone の進行ステータスは自動で更新されますが、**イレギュラーで自動更新されない**ことがあります。**納品済み案件にもかかわらず Desk 上のステータスが「制作中」のままで、契約サマリーを再同期しても変わらない場合**は、PS 側で kintone 内の「**進行ステータス**」を手動で「**納品済み**」に変更してください（Desk の表示もそれに追従します）。

### 17-3. 「アーリー対象」とは

最低契約期間6か月分の費用を事前にご入金いただいている状態です。「アーリー」は社内での呼び方で、対象となるのは主に **創業1年未満の企業様・個人事業主様**。対象のお客様は kintone上で「アーリー対象」が「Yes」になっています。

※ アーリー対象 Yes で6か月経過前の解約依頼をいただいた場合、解約手続き自体は受け付けますが、制作案件中は理由を聞きディレクターに相談してください。

> **アーリー対象の請求・返金ルール（2026-08-31 明確化）**
>
> アーリー対象のお客様は「最初の6か月分は前払いで確定している契約」です。そのため、**最低契約期間より前に解約のご希望があった場合でも、6か月目に解約扱いにする形になり、未利用分の返金はできません**（6か月分の請求・返金ルールは変更できない。これは月額支払いの方も同じです）。
>
> - 例: 2608月で解約を申し出られても、最低契約期間が2609月までであれば、「解約OK／ただし2609月での解約になる」旨をご連絡する。
> - 解約フォームを送る前に、必ず **kintone情報（最低契約期間・他に契約中のサービスの有無・どのクライアントが解約になるか）を確認**してから対応する（1名で複数社・複数サービスを契約しているケースがあるため）。
> - 6か月未満で解約申請された場合の案内は、解約フォーム送信のタイミングで別テンプレートを送る想定（**専用テンプレートは未整備のため、今後作成予定**）。システムで自動判定はされない。

### 20-7. Wixサイトのドメイン接続（納品後のお客様の対応）

納品後の Wix サイトで、ドメインをつなぎ直す・新しくつなぐときの作業です（旧ディレクターマニュアル「ドメイン接続（顧客取得）」「ポインティング接続」「ドメイン接続（弊社取得）」から。2026-10-07 林さん「納品後のお客様の対応で使う」）。AI サイトは [11 章](#11-ドメイン接続) のとおりです。

> 🔒 Wix・バリュードメインのログイン情報は、社内のパスワード管理ツールを参照してください。

#### プレミアムプランについて（共通の前提）

Wix サイトに独自ドメインをつなぐには、そのサイトに**プレミアムプラン**が必要です。まず、解約済みのお客様のサイトから余っているプランを移して使います。

1. Wix のホームで「Ended Partners」（解約されたお客様のサイトの置き場）を開く
2. 「フィルター」で「プレミアム」を選び、プレミアムプランが付いたサイトを探す
3. そのサイトの「…」から「プランを移行」を選ぶ
4. 移す先（ドメインをつなぐサイト）を検索して選び、「次へ」→「はい、移行します」

**移せるプランが無いときは購入する**

1. つなぐサイトで「ドメインを接続」から進み、出てきた画面で「アップグレード」を選ぶ
2. **パーソナルプラン（一番右）**の「選択する」を押す（ほかのプランは選ばない）
3. **12ヶ月**を選び、「お支払いへ進む」（ほかの期間は選ばない）
4. 金額を必ず確かめてから「購入する」

#### A. お客様が取得したドメインをつなぐ（ポインティング接続）

1. 上の「プレミアムプランについて」のとおり、つなぐサイトにプレミアムプランを付ける
2. つなぐサイトの画面で「ドメインを接続」→「ポインティング方式」を選び、Wix の案内に沿って進める
3. お客様のドメインの DNS に次の値を入れる（お客様が入れるときは、この値を案内する。管理会社の調べ方と各社の画面は [11-4](#11-4-先方ドメイン使用)）

    | 種別 | ホスト名 | 値 |
    | --- | --- | --- |
    | A | `@`（空欄の会社もある） | `185.230.63.107` |
    | CNAME | `www` | `pointing.wixdns.net` |

    - 初めからある A レコードと、ホスト名が `www` のレコードは消す
    - **サブドメインでつなぐときは A は変えず**、CNAME を 2 つ（ホスト名なしと `www`）足し、どちらも `pointing.wixdns.net` にする
    - 会社によっては CNAME の値の末尾に「.」が要る（例: バリュードメイン）
4. つながったかを確かめる（[11-5](#11-5-ドメイン対応時の注意事項) の「DNS の設定で気をつけること」も守る。MX・ネームサーバーは触らない、変える前にスクリーンショット）

#### B. 弊社で取得したドメインをつなぐ（ネームサーバー接続）

**ドメインを取る**

1. 依頼されたドメインを [設定依頼管理シート](https://docs.google.com/spreadsheets/d/{DOMAIN_REQUEST_SHEET_ID}/edit) で確かめる
2. バリュードメインにログインし、トップの検索欄でそのドメインを検索する
3. 取得できれば「取得」→「ドメインのみ申し込む」→「次へ進む」。支払いは「クレジットカード」を選び、規約に同意して「申込み確定」（取得できなければ依頼した人に伝える）

**Wix とつなぐ**

1. バリュードメインの「ドメイン」で取ったドメインを検索し、「ネームサーバー」を開いておく（タブは閉じない）
2. 上の「プレミアムプランについて」のとおり、つなぐサイトにプレミアムプランを付ける
3. Wix でそのサイトを開き、上の「ドメインを接続」→ 取ったドメインを検索して「接続する」
4. 「このドメインを取得しています」→「ドメイン接続」→「スタート」。**「移管する」は絶対に押さない**
5. 表示される手順 1〜3 を進め、「コピー」と出るネームサーバーの値を 1 つずつバリュードメインのネームサーバー欄に貼って「保存」→「OK」
6. Wix に戻り「ネームサーバーを置き換えました」を押す。つながるまで 5 分〜半日かかる

**確認と報告**

1. Wix のトップからサイトを検索して URL を開き、つながっているかを確かめる（まだなら時間をおいてもう一度）
2. 依頼した人に「（サイト名）接続完了しました」と伝える
3. お客様への報告は LINE 定型文「【ドメイン接続】接続完了報告」を使う。担当の名前・URL に加え、タイトルとディスクリプションを入れる
    - タイトル・ディスクリプションは、Wix のサイト管理 →「サイト・モバイルアプリ」→ SEO チェックリストの「設定を続行する」で、トップページのタイトルとディスクリプションをコピーする。設定されていなければ、担当のディレクターに「SEO 未設定です」と伝える
4. 設定依頼管理シートと制作進行シートの状態を「完了」にする

### 21-3. AIサイトのブログCMS

> 📌 **お客様がご自身でブログを投稿・編集できるのは、独立したブログページがあるサイトだけ（2026-10-02〜／林さん #director-質問の場）** — サイト内に「ブログ」という記載があっても、ブログページ（1ページ）が**独立したページとして作られていなければ、お客様側でブログを編集・投稿することはできません**。「ブログを自分で更新したい」というお問い合わせには、まずサイトに独立したブログページがあるかを確認してから案内してください。無い場合はブログページを1ページ作る必要があり、契約プランによって対応が変わります。
>
> | 契約プラン | 対応 |
> | --- | --- |
> | BASIC | STANDARD プランへのプランアップが必要 |
> | STANDARD で上限の6ページを使い切っている | (a) ページの構成を変えてブログページを追加する、または (b) 1ページ追加して ADVANCE プランへプランアップする |

#### ケース別対応手順

##### ケースA: 「ブログにログインできない / パスワードを忘れた」

対応は [22-4 ケースC](#ケースc-ログインできない--パスワードを忘れた) と**完全に同じ**です（ブログ専用のパスワードは存在せず、Propagate AI のアカウントを使うため）。

##### ケースB: 「別のスタッフもブログを書けるようにしたい」

ブログの編集権はログインアカウント単位です。以下のどの方法でも結果は同じで、**追加された方には設定メールが自動で届きます**（はじめての方＝パスワード設定メール / 既にログインをお持ちの方＝サイト追加の案内メール）。追加後に PS から個別の設定案内を送る必要はありません。

| # | 方法 | 操作 |
| --- | --- | --- |
| ① | 顧客自身 | マイページ右上「アカウント設定」→「メンバー招待」 |
| ② | PSが代行（顧客詳細から） | 顧客詳細の「アカウント管理」→「メンバーを追加」 |
| ③ | PSが代行（ブログ管理から） | ブログの立ち上げ時や、**ご本人以外のスタッフに渡す**場合はこちら |

**③ ブログ管理からの追加手順**

1. https://www.propagate-ai.com/admin/blog-cms でサイト名を検索 → サイト詳細を開く
2. 「**メンバー管理**」に追加するメールアドレスを入力して追加
3. 完了（相手には設定メールが自動で届きます）

- ③ はサイトとお客様の紐付けも同時に行われるため、「ブログを書く」が出ないときの復旧にも使えます
- 「このサイトは顧客に紐付いておらず…」というエラーが出た場合は、サイトと顧客の紐付けが未設定です。**顧客の登録メールアドレス（kintone の連絡先）で追加**すると自動で紐付きます
- メンバー管理から「削除」しても、相手のログインアカウント自体は消えません（そのサイトへの表示が外れるだけです）

##### ケースC: ログインできたのに「ブログを書く」ボタンが出ない / サイトが表示されない

ブログサイトとお客様アカウントの紐付けに問題がある可能性があります。**開発チームへエスカレーション**してください。

##### ケースD: 「記事が自分のホームページに反映されない」

公開ボタンを押してから反映まで数分かかる場合があります。**10分以上**経っても反映されない場合は開発チームへエスカレーションしてください（サイトの構成によって再ビルドが必要なことがあります）。

##### ケースE: 「サイト公開前だが、先にブログを触れるようにしたい」

制作中（PA運用状態が「**リリース不可 / 準備中**」）のお客様でも**付与できます**。

| # | 渡す相手 | 操作 |
| --- | --- | --- |
| 1 | **お客様ご本人**（＝ kintone の登録メールアドレス） | 顧客詳細 →「アカウント管理」→ オーナー行の「**初回ログイン用メールを送信**」 |
| 2 | **ご本人以外**（広報担当など、別の方のアドレス） | ケースB③（ブログ管理からの追加） |
| 3 | いずれの場合も | 顧客へ**定型文⑦**を送る |

### 22-5. 「お問い合わせ件数」のカウント基準

Propagate AI の「お問い合わせ」件数について、お客様から質問があった場合は以下を案内してください。

- お問い合わせ件数には、**フォーム送信だけでなく、サイト上の電話番号タップ・メールアドレスタップも含まれます**
- **通知メールが届くのはフォーム送信のみ**です（電話番号タップ・メールアドレスタップでは通知メールは送信されません）
- **電話番号タップは 1タップ＝1件**としてカウントされます
- フォーム送信履歴とお問い合わせ件数が一致しない場合があります（弊社のテスト送信はお客様画面では非表示のため）
- ご希望があれば、「お問い合わせ」件数を**フォーム送信のみのカウントに変更**することも可能です（その場合、電話番号タップ・メールアドレスタップは件数に含まれません）

### 22-8. お客様がヒートマップツール（Microsoft Clarity など）を設置したい場合（2026-10-01〜）

弊社の Clarity は PA の分析に使っているもので、**お客様に権限をお渡しすることはできません**。全顧客のサイトを 1 つのプロジェクトにまとめて計測しているため、権限をお渡しすると他社サイトのデータまで見えてしまうためです。選べるのは「弊社の Clarity のまま」か「お客様のツールに置き換える」かの二択です。置き換えても PA の改善提案は止まらず、GA4 のデータで引き続き作られます。ただし、「どのボタン・どの場所で詰まっているか」といったクリック位置などをもとにした部分の具体さが下がります。

**置き換えをご希望の場合**: [設定依頼管理シート](https://docs.google.com/spreadsheets/d/{DOMAIN_REQUEST_SHEET_ID}/) の「先方アドレスClarity接続依頼」シートで、そのお客様の行の K 列（備考）に「置き換え希望」と、受け取ったトラッキングコード、またはプロジェクトの URL を書きます。設置が終わったら、同じ K 列に設置日を書き足し（例: 置き換え希望 / コードまたは URL / 設置日 2026-10-05）、I 列を「完了」にします。H 列（先方メールアドレス）と J 列（完了日）は触りません（書き方は [07 設定依頼管理マニュアル](07-ドメイン-GSC-GA-Workspace設定依頼管理-運用マニュアル.md) の「4. 先方アドレスClarity接続依頼」）。このシートは PA が自動で読むものではなく、人が見て手作業で設置するための受付です（PA が自動で処理するのは「先方GTMタグ設置依頼」シートだけ）。PA 側には置き換えた顧客を記録する場所が無く、**このシートの行が唯一の記録**になるため、設置が完了しても行は消さないでください。

```

</details>

## 23. 電話対応

### 23-1. 使用ツール

- 電話システム：[03plus](https://03plus.net/)
- 受電設定の変更（稼働者に応じた転送先切替）は 03plus の管理画面から行う

※ 操作方法が不明な場合は、経験のあるメンバーに確認すること。

### 23-2. 受電設定の変更

- 稼働者に応じて受電先を変更する（例：的場さんが稼働する日は的場さんに変更）
- 変更は 03plus の管理画面から行う

### 23-3. 留守電対応

- 留守電メッセージは 03plus に設定済み
- 留守電が入った場合は **5分以内に折り返す**こと
- 折り返し前に先方の用件を Slack で確認する

### 23-4. 受電時の対応フロー

1. 電話を受けたら、会社名・担当者名・用件を確認する
2. 制作進行シートまたは kintone で案件を特定する
3. 一次対応として用件を伺い、「担当者から折り返します」と伝える
4. Slack の該当チャンネルで担当者にメンションし報告（先方名、電話番号、用件概要、折り返し希望）
5. Propagate Desk で社内用チケット（電話）を作成する → [10-3](#社内用チケット電話の作成)

### 23-5. 電話対応時の注意事項

- 基本は**テキストベース**でのやり取りをお願いする
- 電話対応が必要な場合は担当者から折り返す
- 電話でのやり取り内容は必ず Slack・Propagate Desk に記録すること

## 24. クレーム対応

### 24-1. クレームの分類と優先度

クレームは以下のレベルに分類し、Slackへの投稿時にタグを付けて共有すること。

#### レベル1（至急対応）

- 先方が激怒している、または強い口調での苦情
- サイトが閲覧不能になっている
- 誤った情報がサイトに公開されている

**タグ**: 「※クレーム、本日対応必須」「※クレーム、電話折り返し必要」
**対応**: 即座に担当ディレクターに Slack メンション＋業務依頼

#### レベル2（早急対応）

- 納期遅延への不満
- 修正漏れ・対応漏れへの指摘
- 担当者の対応品質への不満

**タグ**: 「※クレーム」「※なるはや対応希望」
**対応**: 一次返信＋業務依頼＋Slackで担当者にメンション

#### レベル3（注意案件）

- 苦言や不満のニュアンスを含むメッセージ
- 制作・修正を早めてほしい等の催促

**タグ**: なし（業務依頼の備考欄に「※苦言あり」等記載）
**対応**: 一次返信＋業務依頼

### 24-2. クレーム対応時の注意事項

- **PSの判断で謝罪や補償の約束をしないこと**。一次対応（状況確認中のご連絡）に留める
- 電話対応を拒否されているお客様（メール・LINEのみ対応可）がいるので、過去のやり取りを確認すること
- 前担当者不在時の引き継ぎ漏れによるクレームが発生しやすいため、引き継ぎ時は特に注意すること

## 26. スマートSEO のお客様対応（2026-10-06〜）

スマートSEO のお客様から来る連絡の、用件ごとの返し方と回し先。2026-09-05〜10-05 にスマートSEO の担当者がお客様へ返した 543 通を鈴木貴登さんが分類し、**鈴木広幸さんが決めたもの**（契約の変更の回し先と修正の目安は東さん）。Desk の自動返信（desk-auto-reply）もこの章に従って一次回答する。

- 答えの中身（最低契約期間・料金・修正の決まり・入稿の手順など）は、Desk の QA ナレッジの「スマートSEO｜…」の問いにある
- 「スマートSEO の担当者」= 15 章の「スマートSEOの記事まわり」の行（そのチケットで前にやり取りしたスマートSEO 担当。いなければ鈴木広幸さん）
- **スマートSEO の担当者は、受け取りの返事がすでに返っているチケットに、受け取りを重ねて返さない。作業が終わったときの連絡だけ送る**（広幸さん。9 月は受け取りの返事 111 通のうち 58 通が 2 通目だった）。ただし、修正の方針や作業の中身が整理できないときは、お客様に聞き直す

### 26-1. 解約したい・解約フォームがほしい（解約の意向）

[16-1](#16-1-解約の手順) のとおり PS が対応する（受け取りの返事 → 引き止めのメール〔解約フォーム付き〕→ 担当者へ連携）。受け取りの返事で、フォームの URL や最低契約期間は書かない。

### 26-2. 「いつから解約できるか」「今の契約はどうなっているか」（このお客様の契約の中身）

解約したいとは書いていない、契約の中身の質問。

- 答え方: 案件管理の「サービス開始月」と「月契約記事数」から、最低契約期間（24 記事または 6 か月の長い方）が終わる月を伝え、解約の締め日（10 日までのご入力は当月末、11 日以降は翌月末）を添える
- 記事数を途中で変えている案件は、終わる月がずれることがある。**答えたあともスマートSEO の担当者に回し**、違っていれば訂正する
- 解約を考えている印なので、引き継ぎのメモに「解約」と付ける

### 26-3. 原稿・記事はいつ届くか・いつ投稿されるか

- 原稿の提出は原則毎月 25 日だが、**案件ごとに納品日（案件管理の「納期」）が決まっていて、違うことがある**。推測で「25 日です」と答えない
- 答え方: 案件管理の納期で答える。入稿代行ありは「〜日までに投稿を完了する予定」、なしは「〜日までに原稿をお送りする予定」。お客様の確認待ちのときは、何をお待ちしているか（キーワード・原稿のご確認など）を伝える
- 次のときは日付を答えず、スマートSEO の担当者に回す: 納期まで 3 日以内・納期を過ぎている・遅れの印がある・納期が未設定・聞かれているのが別の月（来月分・先月分など）

### 26-4. 原稿の修正の依頼

- 直す箇所を言い直して受け取り、「修正のご依頼をいただいてから、5〜10 営業日以内に修正いたします」と伝える
- どの記事のどこをどう直すかが読み取れないときは、同じ 1 通で聞く（記事の番号と箇所）
- 納品前の原稿か納品済みの記事か分からなければ、原稿の修正として扱う
- スマートSEO の担当者に回す

### 26-5. キーワードの指定・差し替えの希望

- **そのまま差し替えない。**担当者が検索の観点で確認し（過去の記事と重ならないか、記事にして問題ないか）、調整した案を出し直す（広幸さん）
- 「承知しました、進めます」と即答しない。「ご希望のキーワードを確認のうえ、調整した案をお送りします」と返す
- キーワードが確定したあとの変更は原則できない。ご希望は翌月以降のテーマに使う
- スマートSEO の担当者に回す

### 26-6. 打ち合わせ・電話の希望

- 打ち合わせをするか・日時は、内容を見て人が決める。日時の候補は出さない
- 何についての打ち合わせかが書かれていなければ、それを聞く（広幸さん「何の打合せかを事前に共有してもらう」）
- スマートSEO の担当者に回す

### 26-7. オプションの追加・記事数の変更の申し込み（契約の変更）

- 料金・決まり（画像オプション 1 記事 2,000 円〔税抜〕、記事数は当月 10 日までの連絡で当月分から増やせる、など）は答えてよい
- お客様の希望の月に変えられるとは言い切らない（「来月から変更できます」と書かない）。申し込みの受け取りまで
- スマートSEO の担当者に回す（2026-10-06 東）

### 26-8. Search Console・Google アナリティクスの権限

- 弊社が制作したサイト → 権限は付けていただかず、Propagate AI を案内する（[22-2](#22-2-gsc--ga-の権限付与)）
- 他社が制作したサイト → 権限の付与をお願いする
- どちらか分からないときは、中身に答えずにスマートSEO の担当者に回す

### 26-9. 納品が済んだ記事の修正

- 納品・修正が完了したあとの記事の修正は、基本的に行っていない（広幸さん）
- 「直したい」と頼まれたら、そのことを伝えたうえで受け取り、スマートSEO の担当者に回す（どの記事のどこかが書かれていなければ聞く）

### 26-10. 効果への不満・お詫びが要るもの・請求や解約の交渉

- 中身に答えず、受け取りだけ返してスマートSEO の担当者に回す（見立てやお詫びは人が書く）。不満なら引き継ぎのメモに「苦情」と付ける
- 不満の無い一般の質問（「いつ頃から問い合わせが増えますか」「記事が長いのはなぜ」など）は、QA ナレッジで答えてよい
