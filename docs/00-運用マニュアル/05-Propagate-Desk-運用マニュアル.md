# Propagate Desk とは

メール（info@ / support@）と LINE、その他の問い合わせ手段を**一元管理する社内ヘルプデスク**です。

**対応範囲**: メール（info@ / support@）／ LINE（受信・送信）／ 電話・その他依頼（手動チケット作成）／ kintone との自動連携／ 業務依頼シート転記

| 種別 | URL |
| --- | --- |
| アプリ本体 | https://propagate-desk.vercel.app/ |
| ログイン方法 | 「Googleでサインイン」→ **@propagateinc.com** アカウントを選択 |

# 必須ルール（全員向け）

## ルール1：LINE 返信は必ず Desk のチケットから

LINE 画面から直接返信した内容は **Desk に反映されません**。Desk 上は対応漏れに見え、PS 側で二重対応が発生します。

## ルール2：kintone 未連携チケットを見つけたら line-id を入力

右パネルの「案件」欄が **「未連携」「案件なし」** と表示されているチケットは、kintone レコードに line-id を登録すると、以降のメッセージが自動で正しい案件に紐付きます。手順はこのマニュアルの「LINE と kintone を line-id で紐付ける手順」を参照してください。

## ルール3：オープンチケットの自動アサインと「未解決」の扱い（2026-07-10〜）

チケットがオープンになった際、**自動で「直前に返信した人」が担当者として追加**されます。PS が追いついていない場合でも、担当となり得る人が即座に確認できるようにするためです。

- 直前の返信者が **PS の場合は自動アサインの対象外**です
- 担当者が自動で入っても、**ステータスは「オープン」のまま**です。従来どおり PS が採配・1次返信を行います
- **オープンのチケットも「未解決」に含まれます**（自分が担当で解決済みでない全チケット）
- 自動で割り当てられた際は、**自分が担当か確認を求める DM 通知**が届きます
- **既存サイト修正メンバーは自動採配の対象外**です（毎日稼働しているとは限らないため。再修正は従来どおりメンション等で回します）

## ルール4：制作中のドメイン確認・スマホ確認メールの自動送信停止（AQ列）

ドメイン接続のやり取り中に自動メールが二重に飛ばないよう、**制作進行シートの AQ 列（ドメイン接続ステータス）に値が入っていると、自動 push メールが送信されません**。スマホ版 OK の返信を受けてドメイン接続方法の選択依頼を返す際は、AQ 列で「**ドメイン接続方法確認中**」を選択してください（詳細は PS 運用マニュアル 14 章）。

## ルール5：契約見送り連絡があった場合のチケット割り振り（2026-08-07〜）

先方より**契約見送り**の連絡をいただいた場合、一次返信後は情報共有のためチケットを「**営業**」または「**ゆうこさん**」に割り振ってください。

- 直近で**営業**とやり取りがある場合 → **営業**へ
- 直近で**ゆうこさん**とやり取りがある場合 → **ゆうこさん**へ

## ルール6：チケット採配時は内部メモ or Slack 連携を必ず添える（試験導入・2026-08-21〜）

チケットを他の担当者・ディレクターへ割り振る際は、**内部メモ**（または Slack 連携）を**必ず**添えてください。「わからないから、とりあえず他の人に丸投げ」というスタンスは行いません。判断基準を明文化してナレッジを蓄積し、同様の問い合わせに PS 側でも回答できる範囲を広げていくための試験的な運用です。

特に**ディレクターへの確認が必要と判断してチケットを回す場合**は、内部メモに以下の3点を残してから採配してください。

1. お客様のどの部分・内容について確認が必要なのか
2. 何を確認することが目的なのか
3. PS ではなく、ディレクターへの確認が必要と判断した理由

- ベース側で返信できる内容は、テンプレートの自動返信案を使用するか、わからない部分はチャットボット等で確認する
- それでも回答が見つからない、または自動返信・テンプレートで返すべきでない内容は、**どこがどういう理由でわからないのか**を内部メモに入れてからチケットを採配する

# チケットの見方

## ステータスは4つ

| 表示 | 意味 |
| --- | --- |
| **オープン** | 対応が必要な状態 |
| **依頼中** | 他の部署・担当へ依頼している状態 |
| **保留中** | 待ちが発生している状態 |
| **解決済み** | 対応が完了した状態 |

**オープン・依頼中・保留中の3つが「対応中」**として扱われ、対応期限の計算対象になります。

## 優先度は4つ

**低 / 普通 / 高 / 緊急** の4段階です。クレーム・解約が検知されたチケットは**自動で「緊急」**になります。

## 対応期限はいつになるか

チケットが立った**時刻**で決まります（土日は営業日ではないため翌営業日へ送られます）。

| チケットが立った時刻 | 対応期限 |
| --- | --- |
| **12:00 より前** | **同日の 17:00** |
| **12:00〜16:59** | **同日中（23:59）** |
| **17:00 以降** | **翌営業日の 12:00** |

期限を過ぎたチケットは一覧で**超過表示**になります。解決済みのチケットには期限が付きません。

## 「依頼中」にするとき担当者が必須

依頼中のチケットで担当部署だけを設定しようとすると、「**依頼中チケットで担当部署を設定する場合は、担当者を先に選択してください。**」と出ます。**部署だけ指定して放置すると誰も気付けない**ため、担当者を先に選んでください。

## 依頼分類（カテゴリ）

初期値は **技術サポート / 請求・料金 / アカウント / 機能リクエスト / その他** の5件です。設定画面から追加・変更できます。

# 返信のしかた

## 返信モードと内部メモモードの違い

返信欄には2つのモードがあります。**取り違えると顧客に社内メモが飛びます。**

- **返信モード** … 顧客へ送信されます
- **内部メモモード** … 社内だけに残ります。顧客には届きません

内部メモは**上部に固定**したり、**時系列に表示**したりを切り替えられます。

## AI 返信案を使う

最新の顧客メッセージをもとに AI が返信文を作ります。

⚠️ **AI 返信案は、採用または却下するまで送信できません。**「AI返信案を採用または却下してください」と出ている間は送信ボタンが効きません。

- **採用** すると本文に入り、そのまま編集・送信できます
- **却下** すると自分で書けます

## 自分のラフを AI に整えてもらう

自分で書いたラフな下書きを、**メール / LINE それぞれの体裁に整形**できます。AI 返信案とは別の機能です。整形後に「**整形前の下書きに戻す**」で元へ戻せます。

文章の整え方（言い回し・語尾）は社内で確定したルールに従います。**AI が代替案や締切を勝手に作ることはありません**（入力にある範囲でしか書きません）。

## テンプレートを使う

返信欄から**テンプレート**を選べます。テンプレートと**メール署名**は設定 →「チケット設定管理」で編集します。カテゴリーで分類・並び替えができます。

## 予約送信する

「**送信日時を設定**」で、後の時刻に送信を予約できます。

- ⚠️ **予約は「時」単位**です（分は指定できません）。実際の送信は**毎時0分**に走ります
- 予約の一覧・キャンセルは「**予約送信**」画面から行います
- ⚠️ **予約メッセージの添付ファイルは後から変更できません**

## 送信と同時に解決済みにする

「**送信して解決済みにする**」「**記録して解決済みにする**」で、送信とステータス変更を1回で行えます。

## Slack へ送る

チケットの内容を Slack チャンネルへ送れます。

- チャンネルを選んでから、**メンション**（個人 / `@here` / `@channel`）を選びます
- ⚠️「**チャンネルに担当者が参加していません**」と出たら、その人はそのチャンネルに居ません。招待するか別の方法で連絡してください

## 添付・引用

**ファイル添付**と**画像添付**ができます。LINE では特定のメッセージへの**引用返信**ができ、「引用返信を解除」で外せます。

# LINE の扱い

## LINE の送信先を選ぶ（個人 / グループ）

LINE には **LINE個人** と **LINEグループ** があります。送信前に送信先が表示されます。

- 「**送信先 LINE ID を選択してください**」と出たら、どの LINE へ送るかを選んでください
- 「**LINE送信先を確認できませんでした**」と出た場合は送らず、`#propagate-desk` で相談してください

## LINE と kintone を line-id で紐付ける手順

### Step 1：Desk で line-id をコピー

チケット詳細画面の**顧客情報**にチャネル欄があります。表示されている line-id をコピーします（「LINE IDをコピー」ボタンがあります）。

### Step 2：公式 LINE で該当 LINE を確認

公式 LINE 管理画面で、対象の LINE アカウント（カスタム表示名 = パートナー名）を検索します。

**同じパートナー名で複数の LINE アカウントが出てくる**ことが多いので、今回の連絡が来た LINE がどれかを確認してください。

### Step 3：kintone で該当パートナー名を検索

kintone でも同じパートナー名で検索すると、**そのパートナーの全レコード（= 全サービス／案件）**が表示されます。

### Step 4：公式 LINE と kintone を見比べて対応関係を判断

公式 LINE 側の**各 LINE アカウントがどのサービス（kintone レコード）に対応するか**を確認します。過去メッセージの内容、カスタム表示名のサフィックス、社内ナレッジなどから判断してください。

### Step 5：kintone の該当レコードに line-id を入力

kintone レコードの line-id 列に、Step 1 でコピーした line-id を貼り付けて保存します。

- 1つの LINE が複数の案件にまたがる場合 → 該当する**全レコード**に**同じ line-id**
- 案件ごとに別の LINE がある場合 → それぞれのレコードに**別々の line-id**

保存後はシステムが自動同期し、そのチケットが正しい kintone 顧客に紐付きます。以降の同じ LINE からの連絡も自動で振り分けられます。

⚠️ **line-id を間違えると別人のメッセージが流入します。**必ずコピペで、迷ったら独断で記入せず確認してください。

# 顧客・案件の情報（右パネル）

## Push の送信先を選ぶ（Push送信チャネル）（2026-08-27〜）

右パネルの**顧客情報タブ**に「**Push送信チャネル**」があります。制作進行シートからの自動 push（自動メール）を**どの宛先に送るか**をここで選べます。

- **自動（LINEが1件ならLINE、それ以外はメール）** … 既定。LINE が1件だけ紐づいていれば LINE、そうでなければメールに送ります
- **メール：〇〇（連絡用）／（登録）など** … 特定のメールアドレスを指定して送ります（候補は「送信先を検索」で絞り込めます）

**使いどころ**: 「**自動メールの送信先だけ指定アドレスに送信希望**」という顧客要望への対応です。登録メールアドレスは1つしか持てず、変更すると契約等のメールの送信先も変わってしまうため、**登録アドレスは変えずに** Push送信チャネルだけを希望のアドレスへ切り替えます。

## kintone の情報を最新にする

右パネルに kintone レコードが表示されます。「**契約サマリーをkintoneから再同期**」で最新化できます。「**Kintone同期・未更新**」と出ている場合は、まだ一度も同期されていません。

## 進行ステータス（制作中／納品済み）（2026-09-01〜）

案件が「**制作中**」か「**納品済み**」かは、kintone に追加された「**進行ステータス**」フィールドで管理されます。**Desk 上の制作中／納品済みの表示も、このフィールドをベースに**表示されます。

| 進行ステータス | 該当するもの |
| --- | --- |
| **制作中** | ・すでに制作進行（制作進行シート）にあるもの<br>・今後、サブWEBの受注ステータスが J になったもの |
| **納品済み** | ・制作中ではなく、すでにサブWEBの受注ステータスが J のもの<br>・今後、Propagate AI に登録されたもの |

⚠️ 表示と実態が違う（制作中なのに納品済みになっている等）案件を見つけたら、**kintone の「進行ステータス」を手動で変更**してください（Desk の表示もそれに追従します）。

## 重要事項の再生成

顧客ごとの重要事項は**自動生成**されます。内容が古いと感じたら「**重要事項を再生成**」を押してください。

## クレーム／解約ラベルを外す

クレーム・解約のラベルは自動で付きます。外すときは確認ダイアログが出ます。

⚠️ **解除すると、そのパートナーに紐づく全チケットのラベルが外れます。**1件だけ外すことはできません。

## パートナー単位のメモ

顧客メモはパートナー単位で保存されます。**保存せずに画面を移動しようとすると警告が出ます。**

# ダッシュボードの「担当顧客」

## 「担当顧客」はどう決まるか

**メンバー管理に登録した「kintone 担当者名」（苗字）**が、次のどちらかに入っているかで判定します。

- kintone の「**営業・受注担当**」 → 担当営業として表示
- **制作進行シートの担当ディレクター** → 担当ディレクターとして表示

つまり **Desk 側で顧客を1件ずつ紐付ける操作はありません。**名前が一致すれば自動で出ます。

## 担当顧客のチケット欄が空白になっている

**原因のほとんどは「kintone 担当者名」が未設定**です。未設定だと判定そのものができず、空で返ります。

**直し方**

1. Desk の **設定 → メンバー管理**を開く
2. 対象のメンバーを編集し、「**kintone 担当者名**」に**苗字だけ**入力する（例: 森）
3. 保存する

**誰が直せるか**

- **管理者** … 全メンバー分を編集できます
- **本人** … 自分の分だけ編集できます
- **閲覧者ロール** … 編集できません（管理者に依頼してください）

**入力しても空白のままのとき**

名前が**一致していません**。次を確認してください。

- kintone の「営業・受注担当」に入っている表記と**同じ苗字**か（フルネームや旧姓になっていないか）
- **担当ディレクター**として出したい場合は、制作進行シートの director 列に名前が入っているか。Desk 側は 設定 →「**担当ディレクター同期**」で読み込みます
- そもそも kintone / 制作進行シート側にその人が担当として設定されているか

⚠️ **Desk 側だけ直しても、kintone や制作進行シートに担当として入っていなければ表示されません。**

# 自動で動くもの（知らないと誤解します）

営業・PS の操作がなくても Desk が自動で行っている処理です。**「誰かが手でやった」と誤解しやすい**ので把握しておいてください。

## クレーム・解約の自動検知

顧客からのメール / LINE を AI が判定し、クレームまたは解約と判定すると自動で次を行います。

1. チケットの**優先度を「緊急」に変更**
2. **クレーム用／解約用の Slack チャンネルへ通知**

⚠️ 誤検知もあります。違う場合はラベルを外してください（全チケットに及ぶ点に注意）。

## 直前リスケ・アポキャンセルの検知

予約の文脈でリスケ・キャンセルの言い回しが出ると、AI が判定して **Slack へ通知**します。

## 営業へ振られた案件の通知

**解約・クレーム / 契約**の分類、または**緊急**の案件が営業へ振られると、`sales-desk対応` チャンネルへ**即時通知**されます。

さらに、**前日18時より前に営業へ振られて翌朝9時時点で未対応**の案件は、まとめて通知されます。

## 依頼チケットのリマインド

ステータスを「**依頼中**」にする、または担当者を追加すると、担当者へ**即座に Slack DM**が飛びます。その後も未対応なら**リマインド**が届きます（平日 10時 / 13時 / 16時 / 19時ごろ）。

依頼中でなくなる、または担当者から外れると、リマインドは止まります。

## 宛先不明メール（バウンス）の通知

送ったメールが届かなかった場合、Slack へ通知されます。**初回アポ前の案件**については架電担当にもメンションが飛びます。

## 空のチケットの自動削除

メッセージが1件も無いチケットは自動で削除されます。

## 制作進行シートからの自動 push

制作進行シートの状況に応じて、顧客へ自動でメールが送られます。**AQ列に値が入っていると止まります**（ルール4参照）。送信先は右パネルの「**Push送信チャネル**」で切り替えられます（「Push の送信先を選ぶ」参照）。

# 業務アシスタントBot（チャットボット）

## どこから使うか

ログインしていれば**どの画面でも右下のボタン**から開けます。「業務アシスタントBotを開く」です。

- 質問は **Enter で送信 / Shift+Enter で改行**
- 会話は履歴として残り、「**新しい会話**」で切り替え、「**過去の会話**」から呼び戻せます

## 何を答えられるか

**ナレッジ（Q&A）**と**マニュアル**を検索して答えます。回答には**出典が番号付きで表示**され、クリックすると元の資料を確認できます。

⚠️ **根拠が見つからない場合、Bot は推測せず「ナレッジ・マニュアルに根拠が見つかりませんでした」と答えます。**これは故障ではありません。統括に確認してください。

⚠️ **答えられなかった質問は記録されます。**設定の「ナレッジ追加」に溜まるので、回答を追加すると次から答えられるようになります。

## Bot が答えられなかった質問に回答を足す（ナレッジ追加）

設定 →「**ナレッジ追加**」を開きます。

1. 左の一覧から質問を選ぶ
2. **正しい回答を入力**する
3. 「**ナレッジに整形する**」で体裁を整える
4. 「**ナレッジに登録**」で確定 → **その場でチャットBotの検索対象に入ります**

不要な質問は「**候補から削除**」で消せます。

## AI が拾った候補を承認する（ナレッジ承認）

送信済みの返信から、AI が「他のお客様にも当てはまる回答」を**自動で候補**として拾っています。設定 →「**ナレッジ承認**」で確認します。

- **承認**すると、**AI 返信案の検索対象（本番ナレッジ）に反映**されます
- **却下**すると削除されます。⚠️ **却下は取り消せません**
- カテゴリ・キーワード・source で絞り込めます
- 「該当チケットを別タブで開く」で元のやり取りを確認できます

⚠️ 候補は**そのまま本番には入りません**。人が承認するまで AI 検索には出ません。

## マニュアルを取り込む（マニュアル設定）

設定 →「**マニュアル設定**」で、GitHub 上の Markdown をチャットボットの検索対象にできます。

- **毎日 深夜3時ごろに自動で取り込まれます。**普段は手動操作は不要です
- すぐ反映したいときは「**取り込む**」または「**設定済みをすべて取り込む**」を押します
- **GitHub 側に変更が無ければ「変更はありませんでした」と出ます**。これは正常です
- マニュアルを新規追加した直後は「**内容はまだ取り込まれていません**」と出ます。取り込みを実行してください

## ナレッジとマニュアルの使い分け

| | 検索するのは | 用途 |
| --- | --- | --- |
| **ナレッジ（Q&A）** | **AI 返信案 と チャットボットの両方** | 顧客への回答になる内容 |

⚠️ **顧客への返信案に出したくない社内手順は、ナレッジではなくマニュアルへ入れてください。**ナレッジに入れると顧客宛の返信案に混ざります。

# 困ったとき

## 送信ボタンが押せない

「**AI返信案を採用または却下してください**」と出ていないか確認してください。AI 返信案が未処理のままだと送信できません。

## 顧客に届いていない / 送信できない

`#propagate-desk` チャンネルで**すぐに**報告してください。Slack DM ではなく**公開チャンネル**のほうが対応が早いです。

## LINE の返信が Desk に出てこない

LINE 画面から直接返信していませんか。**LINE 画面からの返信は Desk に反映されません**（ルール1）。

## チケットが「未連携」「案件なし」のまま

kintone に line-id が登録されていません。「LINE と kintone を line-id で紐付ける手順」を実施してください。

## 「依頼者または担当者のみ操作できます」と出る

業務依頼の画面で、自分が依頼者でも担当者でもないチケットを操作しようとしています。担当者に依頼してください。

## 担当顧客のチケットが表示されない・空白

設定 → メンバー管理の「**kintone 担当者名**」が未設定です。**苗字だけ**入れてください。管理者は全員分、本人は自分の分を直せます。詳しくは「ダッシュボードの『担当顧客』」の節を参照してください。

## Bot が「根拠が見つかりませんでした」しか返さない

ナレッジにもマニュアルにもその情報がありません。**故障ではありません。**統括に確認したうえで、設定の「ナレッジ追加」から回答を登録すると次から答えられます。

## マニュアルを更新したのに Bot の答えが変わらない

取り込みは**1日1回（深夜3時ごろ）**です。すぐ反映したい場合は設定 →「マニュアル設定」→「取り込む」を実行してください。

## 予約送信した時刻ちょうどに送られない

**予約は「時」単位**で、送信は**毎時0分**に走ります。分単位の指定はできません。
